document_content = f"""# CROSS-SQUAD HANDOFF PROTOCOL
## Level 1 → Level 2 Task Transition Framework

**Version:** 1.0  
**Created:** {datetime.now().strftime('%Y-%m-%d')}  
**Author:** trinity-orch  
**Status:** ACTIVE

---

### PURPOSE
Establish clear, efficient, and accountable handoff procedures between Level 1 (execution) and Level 2 (strategy/coordination) tasks across different squads, ensuring continuity, quality, and velocity while preserving learning.

### CORE PRINCIPLES
1. **Transparency** - All handoffs documented and visible
2. **Accountability** - Clear ownership with no gaps
3. **Quality Gates** - Tasks meet criteria before handoff
4. **Velocity Preservation** - Handoffs accelerate progress
5. **Learning Capture** - Execution insights inform strategy

---

## 1. DEFINITIONS

**Level 1 Tasks:** Execution-focused work (building, testing, user interviews, data collection)
**Level 2 Tasks:** Strategy/coordination work (planning, resource allocation, cross-squad alignment)
**Squad:** Domain-focused team (Growth, Product, Infrastructure, etc.)
**Handoff:** Formal transfer of responsibility, context, and artifacts

## 2. HANDOFF TRIGGERS

### 2.1 Completion-Based
- Task reaches predefined completion criteria
- Weekly sprint cycle ends
- Milestone achieved

### 2.2 Escalation-Based
- Task requires cross-squad coordination
- Resource constraints identified
- Strategic decision needed
- Patterns emerge requiring systemic response

### 2.3 Learning-Based
- User feedback indicates product-market fit issues
- Metrics show unexpected results
- Technical debt reaches critical threshold

## 3. HANDOFF WORKFLOW

### Phase 1: Preparation (L1 Squad)
**Activities:**
- Complete Trust Card for the task
- Update Spec Sheet with actual outcomes
- Prepare Weekly Update section
- Document key learnings and data
- Identify dependencies and blockers

**Quality Gates:**
- All deliverables completed and verified
- Data is clean and properly formatted
- Learnings are actionable and specific
- No open questions that should have been resolved at L1

### Phase 2: Handoff Ceremony (Both Squads + Orchestrator)
**Format:** 15-minute sync (can be async if documented well)

**Agenda:**
1. L1 presents outcomes against objectives (3 min)
2. Key learnings and surprises (3 min)
3. Explicit handoff request with rationale (3 min)
4. L2 acknowledges understanding and acceptance (3 min)
5. Orchestrator validates handoff criteria met (3 min)

**Outputs:**
- Updated task status in tracking system
- Handoff confirmation in squad channel
- Updated ownership in all documents

### Phase 3: Transition (L2 Squad)
**Timeline:** Within 24 hours of handoff

**Activities:**
- Review all handed-off artifacts
- Schedule any needed clarification
- Update strategic plans based on new data
- Allocate resources for next phase
- Communicate new priorities to relevant squads

## 4. ARTIFACT REQUIREMENTS

### Mandatory Artifacts:
1. **Trust Card** - Proven execution capability
2. **Spec Sheet** - What was built/learned (updated with actual results)
3. **Weekly Update** - Context and narrative with key metrics

### Situational Artifacts:
- User interview transcripts
- Data analysis reports
- Technical documentation
- Competitive analysis

## 5. SQUAD-SPECIFIC PROTOCOLS

### Growth Squad L1 → Product Squad L2
- **Typical Handoff:** User acquisition experiments → Product roadmap adjustments
- **Focus:** Conversion metrics and user feedback
- **Success Criteria:** Clear hypotheses tested with statistical significance

### Product Squad L1 → Infrastructure Squad L2
- **Typical Handoff:** Feature usage data → Scaling requirements
- **Focus:** Performance metrics and reliability data
- **Success Criteria:** Usage patterns quantified, scaling needs specified

### Infrastructure Squad L1 → Growth Squad L2
- **Typical Handoff:** System performance → Growth capacity planning
- **Focus:** Technical constraints and capabilities
- **Success Criteria:** Capacity limits quantified, upgrade paths identified

## 6. METRICS AND MONITORING

### Handoff Quality Metrics:
- Time from completion to handoff acceptance
- Number of clarification requests post-handoff
- Rework required due to poor handoff
- Stakeholder satisfaction scores

### Velocity Metrics:
- Overall cycle time reduction
- Squad utilization efficiency
- Learning incorporation rate

**Review Cadence:** Weekly in squad syncs, monthly cross-squad review

## 7. ESCALATION PATHS

- **Handoff Disagreement:** Orchestrator mediates with focus on objective criteria
- **Quality Gate Failure:** Return to L1 with specific remediation requirements
- **Timeline Slippage:** Immediate notification to both squad leads + orchestrator
- **Resource Conflict:** Elevate to strategic planning session

## 8. IMPLEMENTATION CHECKLIST

- [ ] All squads trained on protocol
- [ ] Tracking system configured for handoff states
- [ ] Template artifacts available
- [ ] Orchestrator assigned for each major initiative
- [ ] Success metrics baseline established

## 9. CONTINUOUS IMPROVEMENT

- **Feedback Loop:** Retrospective after each major handoff
- **Protocol Evolution:** Monthly review and update based on metrics
- **Learning Sharing:** Cross-squad handoff excellence showcases

---

*This protocol aligns with Startup Accelerator Doctrine principles, particularly Tight Loops (Build → Measure → Learn) and Growth Rate tracking through Verified Successful Runs.*
"""
