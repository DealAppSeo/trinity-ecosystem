# ANTIFRAGILE Prevention Spec: task_failed (Task ID: 119295)
**Date Analyzed:** 2026-02-05  
**Failure Volume:** 48,090 in 7 days  
**Root Causes:** Executor reporting desync (Airflow/Celery)[1], timeout config absence (Temporal)[2], launch mismatches (ECS Fargate)[4], resource errors[5].  
**Prevention Measures:**

## 1. Configuration Validation Hook (Immediate)
- **Airflow:** Enforce `default_args` with `retries=1, retry_delay=timedelta(seconds=5), execution_timeout=timedelta(minutes=10)`. Add `on_failure_callback` logging executor state.[1]
- **Temporal:** Mandate `ActivityOptions` with `StartToCloseTimeout` and `ScheduleToCloseTimeout` (e.g., 10min). Workflow code: `activity_options = ActivityOptions(start_to_close_timeout=timedelta(minutes=5))`.[2]
- **ECS:** Pre-launch check: Match task definition `requiresCompatibilities` to cluster capacity provider. Validate subnet IP availability via `describe-subnets`.[4]

## 2. Monitoring & Auto-Recovery
- Deploy healthcheck DAG/workflow: Scan logs for "return code 0" + "SUCCESS" but failed state; auto-requeue via `trigger_dag` or `Workflow.terminate()`.[1][2]
- Alert on categories: TaskFailedToStart, InternalError (>5% rate).[5]
- Metrics: Track "Verified Successful Runs" WoW per STARTUP DOCTRINE.

## 3. Infrastructure Fixes
| Issue | Fix | Source |
|-------|-----|--------|
| Subnet IP exhaustion | Create new private subnets; disable public IP on awsvpc.[4] |
| Agent disconnect | Restart ECS agents; use EC2 describe-instances for status.[4][5] |
| Missing inputs | Add input validation operator (e.g., BashOperator with file checks).[3] |
